# Local-first account transitions

Signing in, signing out, restoring a Firebase session, or switching accounts does not by itself load, merge, upload, reassign, overwrite, or delete the active note library. The auth observer only changes in-memory library ownership state; when leaving an account-bound library, it restores a locally saved library snapshot in memory. That path reads local storage/IndexedDB but does not write note storage, Firestore, attachments, or deletion markers. If a local snapshot cannot be read, the transition fails closed to an empty in-memory library rather than displaying the previous account's notes.

A device-local library remains local after sign-in. PWA note saves and reconnect retries are blocked from Firestore unless the active library UID exactly matches the signed-in Firebase UID. Attachment retries no longer run from the auth-change event and are blocked unless both the active library and the stored attachment owner match the current account; legacy or mismatched files are not claimed automatically. Shared localStorage note/folder snapshots are read or replaced only when their recorded library owner matches, while each library's durable IndexedDB snapshot remains separate.

## Starting the PWA sync

The Sync Center is the explicit entry point for first-time account sync. It waits for the local-library load, requires a matching durable local backup, checks account-deletion status, and warns before combining device and cloud notes, syncing deletion markers, or retrying attachment work. Cancelling or failing preflight leaves the device library in local mode.

## Private Notes and Mobile preview

PWA local snapshots continue to keep encrypted Private Notes alongside the local library. For Firestore, the next successful PWA sync first reads the existing root, active, and listed retained library snapshots, then writes each valid encrypted private record to `users/{uid}/privateNotes/{encodedNoteId}` and reads it back. Before enabling that sync, a trusted Admin must inventory every account and resolve every unlisted legacy revision in the client-unwritable `privateNotesMigrationPreflights/global` manifest. The PWA rejects a global completion label unless the manifest's account count and entries match, every account's unlisted-revision count matches its explicit resolutions, and retained revisions are already listed in that account's `inactiveLibraryRevisions`; an `admin-reviewed` resolution also needs a documented disposition, reviewer, and timestamp. Aggregate counts do not identify which account owns a revision and are not sufficient to open the gate. This browser client cannot discover page subcollections whose revision IDs are absent from the account document. Legacy private metadata is re-encrypted in the browser only while Private Notes are unlocked. After verification, the PWA replaces legacy plaintext in the account's active local snapshot and verifies both IndexedDB and the account-owned localStorage root before ordinary cloud pages can change. If preservation, local persistence, or read-back verification fails, the sync stops before staging or switching the ordinary library snapshot. Divergent encrypted variants are kept in owner-only `privateNoteVersions` documents and displayed as labeled recovered copies so they remain available to inspect and restore.

After verified preservation, the PWA writes a `privateNotesSchemaRequired` compatibility fence and a fresh schema nonce before staging pages; it marks `privateNotesSeparated` only with the successful filtered-library pointer commit. Offline-deletion-marker or account-deletion writes can establish the compatibility fence earlier without claiming separation is complete. Schema-v3 pages omit private records. Only a fully matching signed-in UID can read or write the private records. The Firestore rules require fresh nonces on account-root writes and page updates, so older clients cannot inherit the v3 marker through merge writes and stop writing as soon as the rules are deployed. Coordinate the rules rollout with the updated PWA; do not promise old-client sync compatibility. The separate store is not used by Mobile; Mobile cloud previews remain read-only and must not write to Firestore.

This change adds code and tests only. It does not run a live migration, change live Firestore data or rules, or deploy. Before release, the owner must review and merge the owner-only rules from `firestore.rules` into the active Firebase ruleset without replacing unrelated project rules, then verify the production rules and app version before allowing sync.
